# Physical annotation and hierarchy fix — native rerun

The fresh Altium Designer Professional **26.11.1** rerun now matches every
compiled membership in both qualification projects:

| Case | Before fix | After fix, fresh forced compile |
| --- | --- | --- |
| Bluetooth Sentinel, complete annotated hierarchy | Parser 70 components/220 pins versus native 72/224; 34 exact memberships | **72 components, 224 pins, 224 exact memberships; zero missing or extra tuples** |
| Single-sheet microcontroller control | 15 components, 65 matching memberships | **15 components, 65 exact memberships; no regression** |

The comparison uses the full `(physical reference, pin, net)` set, including
isolated pins. Counts alone are not the acceptance condition. The saved parser
does not read the native expected-membership file until comparison; no native
rows are used to manufacture its output.

## What changed

The shared file-analysis integration remains in `hw-skills`, using Universal
Netlist **1.14.4** plus the scoped **Altium adapter v1**. Native capture and
qualification remain in `altium-tools`. The adapter does not modify the installed
npm package or source design files. Modified upstream project/channel orchestration
retains Apache-2.0 attribution, LICENSE and NOTICE; the annotation matcher and
new synthetic fixtures are original code.

- **Physical identity precedes connectivity.** The original reader merged sheets
  using logical references, so distinct `R9`/`R10` components could collapse.
  Annotation now resolves each instance before extracting its nets, which also
  gives autogenerated pin nets the correct physical reference.
- **Annotation is joined by source identity.** The full instance/component UID,
  document, logical reference and part are checked. Where an old sheet-symbol UID
  survives in the annotation file, a stable component UID plus document and named
  channel can resolve it uniquely. Both UID paths and the matching basis remain
  in the report. This case used 55 full-UID matches, 14 component/channel matches,
  and 5 unchanged schematic identities across 74 symbol parts (72 packages).
- **Local power stays local.** A power object wired to a port in a hierarchical
  design must connect outward through that port's sheet entry. The earlier
  reader incorrectly joined these supplies globally, merging `VBAT` with `PIO2`
  in the example. The corrected scoping follows
  [Altium's documented power-port exception](https://www.altium.com/documentation/altium-designer/schematic/creating-circuit-connectivity).
  Ordinary global power ports still join globally.
- **Isolated pins retain their names.** The underlying query model discarded
  singleton nets and normalized those pins to `NC`. The Altium project adapter
  retains the extractor's generated pin-net names, matching compiled membership.

Incomplete, ambiguous, stale/unresolved, reused or colliding annotations fail
explicitly. Missing/cyclic hierarchy and duplicate schematic basenames are also
refused. Repeated-channel and multi-part behavior has regression coverage.
Annotated assembly variants remain **blocked** until they receive native
qualification; this change does not guess how to apply them. Existing
unannotated variant/DNP tests continue to pass.

## Native procedure and preservation

Fresh disposable copies were prepared from the installed Bluetooth Sentinel
example and the existing single-sheet control. The tested
[native capture template](../altium-design-review/scripts/native_membership_capture.pas)
opened each exact project, opened a schematic and ran
`DM_CompileEx(True, Cancelled)`. Both native captures succeeded without dismissed
dialogs, exported complete memberships, and closed the disposable projects.
The installed `hardware-design-review` junction was used for the comparisons.

All 32 pre-existing files in the complete copy and all 3 control source files
retained their hashes. Before/after workspace project/document states matched;
focus restoration succeeded after the batch. The raw native results, TSVs,
comparison JSON, source manifests and rendered scripts remain in private local
evidence. The [machine-readable record](native-connectivity-fix-2026-11-12.json)
publishes aggregate results and artifact hashes, without vendor source files or
private workspace paths.

The integration suite now has **35 tests: 24 connectivity and 11 manufacturing**.
The ten added connectivity cases cover annotation collisions, local/global power,
stable-UID fallback, malformed/stale annotation, isolated pins, repeated channels,
multi-part symbols and invalid hierarchy. The full native rerun is independent
of those synthetic expectations.

This supersedes the connectivity failure in the
[initial qualification](native-qualification-2026-11-12.md), which remains as
historical evidence. CAM findings from that session are unchanged; no new CAM,
variant, ERC/DRC, fabrication-profile or supplier DFM qualification is claimed.
Interactive assembly remains deferred.
